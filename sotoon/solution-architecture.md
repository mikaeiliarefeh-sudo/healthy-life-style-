# راه کار (Solution Architecture) — مصرف آی‌پی پابلیک

> تکمیلِ بخشِ «راه کار» داکیومنت. ایده‌های محصولی + معماریِ پیشنهادی، نگاشته‌شده به مسائلِ مستندشده.

## اصلِ کلی — دو الگو که بیشترِ مسائل را یکجا حل می‌کند
- **سمتِ ساخت → «کمترین آی‌پی» پیش‌فرض:** VM به‌صورت پیش‌فرض خصوصی (بدونِ آی‌پیِ پابلیک)؛ اینترنت یک تصمیمِ صریحِ هزینه‌دار.
- **سمتِ حذف → «مرورِ وابستگی‌ها هنگامِ حذف» (deletion-time dependency review):** حذفِ هر ریسورس یک صفحه‌ی مرور باز می‌کند که آی‌پی‌های مستقیم + ریسورس‌های وابسته + هزینه‌ی ماهانه‌ی هرکدام را با دکمه‌ی نگه‌داشتن/حذف نشان می‌دهد.

## ۱) ساختِ VM — آی‌پیِ دوگانه (روی VPC + روی VM)
ریشه: کاربر هم‌زمان می‌تواند VPC را متصل به اینترنت کند (آی‌پیِ گیت‌وی) و هم روی VM آی‌پی بگذارد → دو آی‌پی، در حالی که اغلب صفر تا یک لازم است.

**سلوشن:** این دو آی‌پی دو کارِ متفاوت‌اند (گیت‌وی = خروجیِ مشترک، آی‌پیِ VM = ورودیِ اختصاصی). به‌جای دو تیکِ جدا، **یک تصمیمِ صریح: «این VM چطور به اینترنت وصل شود؟»** با سه گزینه‌ی هزینه‌دار:
- **فقط خروجی (خصوصی، از گیت‌ویِ VPC)** → ۰ آی‌پیِ اضافه — پیش‌فرض
- **ورودی از طریق LoadBalancer (اشتراکی)** → ۱ آی‌پی برای چند VM — پیشنهادی برای سرویس
- **آی‌پیِ اختصاصی روی VM (دوطرفه)** → ۱ آی‌پی به‌ازای هر VM — فقط برای نیازِ هویتِ پابلیکِ مستقل

اگر کاربر هم آی‌پیِ اختصاصیِ VM بزند هم گیت‌ویِ VPC → هشدار: «برای خروجی هر دو لازم نیست». تعداد/هزینه‌ی آی‌پی زنده کنارِ انتخاب نشان داده شود.

## ۲) برداشتنِ کانسپتِ رزرو/موقتی
تصمیم مالِ زمانِ حذف است، نه ساخت.
- **زمانِ ساخت: هیچ انتخابِ رزرو/موقتی نیست.** آی‌پی فقط «متصل به ریسورس» است.
- **زمانِ حذفِ ریسورس:** «آی‌پیت را نگه می‌داری یا آزاد می‌کنی؟» — پیش‌فرض = **آزاد**. اگر نگه داشت → رزروِ بی‌اتصال، و همان‌جا: «قیمتِ رزروِ بی‌اتصال بالاتر است».
- همین پرسش، خودِ «یاداوریِ» گم‌شده است → مشکلِ نوتیف‌نکردن هم حل می‌شود.

## ۳) حذفِ کلاستر کوبر — صفحه‌ی «مرورِ پاک‌سازی»
با حذفِ کلاستر، صفحه‌ای همه‌ی منابعِ متصل به کلاستر را لیست کند: workerها/control-plane (خودکار)، LBهای کلاستر + آی‌پی‌هایشان، VPC/subnet، آی‌پی‌های پابلیک. برای هر آیتم:
- نوع، نام، **مختصِ همین کلاستر یا مشترک** (VPCِ مشترک → پیشنهادِ حذف ندهد/هشدار)، **هزینه‌ی ماهانه**، دکمه‌ی نگه/حذف.
- کلیک روی هر منبع → منابعِ خارجِ کلاستر که به آن وصل‌اند را یک سطح باز کند.
- پیش‌فرض: مختص‌ها حذف، مشترک‌ها نگه با نوت. یک تأیید → حذفِ آبشاری.

## ۴) حذفِ VPC — تبِ مرور
تبی که subnetها + ماشین‌ها + LBها + آی‌پی‌های متصل را با هزینه‌ی ماهانه و دکمه‌ی نگه/حذفِ هرکدام نشان دهد + یک اکشنِ آبشاری. جایگزینِ فلوی تو در توی چند-تبیِ فعلی.

## ۵) حذفِ VM — تشخیصِ والدِ خالی (رو به بالا)
موقعِ حذفِ VM:
- آی‌پیِ مستقیمِ خودِ VM → بپرس نگه/آزاد.
- **تشخیص بده بعد از رفتنِ این VM، subnet/VPCش خالی می‌شود یا نه:**
  - خالی می‌شود → پیشنهادِ حذفِ subnet/VPCِ خالی + آی‌پیِ گیت‌ویش.
  - مشترک است → فقط اطلاع بده، دکمه‌ی حذف نده (یا disable با نوتِ «مشترک با N ریسورس»).

> subnet/VPC معمولاً مشترک است؛ نباید موقعِ حذفِ یک VM کورکورانه پیشنهادِ حذفِ VPC داد. این دقیقاً حالتِ ۲ (VPCِ بدونِ سرور) را سرِ منبع خفه می‌کند.

## ۶) اصلِ واحدِ حذف (تعمیمِ ۳ تا ۵)
برای هر ریسورسی که حذف می‌شود:
- آی‌پیِ پابلیکِ **مستقیم** → «نگه یا آزاد؟» (پیش‌فرض آزاد، هزینه‌ی نگه‌داشتن نشان داده شود).
- **ریسورسِ دیگر** (VPC/subnet/LB) وصل است → «اینها را هم حذف کنم؟» با تفکیکِ مشترک/مختص و هزینه‌ی ماهانه‌ی هرکدام جلویش.
- یک تأییدِ نهایی، آبشاری.

## ۷) رفعِ باگ‌ها
- حذفِ آبشاریِ کلاستر (subnet+VPC+IP).
- باگِ LBِ نصفه (انصراف → آی‌پیِ یتیم).
- پیامِ خطای درست هنگامِ تمام‌شدنِ رنجِ آی‌پی.

## ۸) بازپس‌گیریِ موجودی
- ۶۴ آی‌پیِ `ske-` (سیستمی، بدونِ دخالتِ کاربر) + ۱۷ تستی → فوری.
- ۱۴۱ non-ske + ۹۷ VPCِ بدونِ سرور → با نوتیف + تأییدِ نبودِ ترافیک.

## ۹) بازدارنده (بعداً)
- قیمتِ گران‌ترِ idle (رزروِ بی‌اتصال).
- TTL / حذفِ خودکارِ با هشدار برای بی‌استفاده‌های قدیمی.
